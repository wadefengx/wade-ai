# 2026-08-05 — Runtime Operating Model 2.0 升级

## 动机

v1(AI_DEV_INSTRUCTION.md)是"AI-Native 开发体系说明书";v2 把 Agent Prompt 升级为 **AI 软件工程运行时(Organization Runtime)规范**——从"告诉 AI 怎么做项目"变成"定义 AI 组织如何自主运转"。方向:Agent Coding Assistant → AI Software Organization Runtime。

## 升级内容

| v1 | v2 |
|---|---|
| 新项目 15 分钟起步模板 | 自改进 AI 工程组织运行时规范 |
| 需求提出 → PM 系分 → lane 并行 | **Intent → Discovery → Spec → Plan → Execute → Verify → Review → Memory → Skill** 全生命周期 |
| Skill = 可复用技能目录 | **可执行组织能力**(1% 可能相关就 MUST invoke,先于一切动作) |
| 固定角色(PM/Arch/UX/FE/BE/QA) | **动态专家 Subagent**(按目标组队,model 分层:机械→便宜,架构/终审→最强) |
| harness + 浏览器实测 | + **Iron Law**:无当轮新鲜验证证据,禁止宣称完成 |
| lane 并行开发 | **Goal-Driven Loop**(Observe→Decide→Act→Verify→Adjust)+ 修复环 |
| memory/skill 回流 | + **Self-Evolution Loop**(分析任务历史/失败/纠错,改进指令本身) |

## 吸收的机制(obra/superpowers)

- **HARD-GATE**:设计未获用户批准前禁止写代码(哪怕"只是一个 todo 列表")
- **Spec 四项自检 + 用户签收**:占位符 / 矛盾 / 歧义 / 范围
- **bite-size 任务**:2-5 分钟一步(写失败测试→看到失败→最小实现→看到通过→commit),禁占位符
- **ledger 文件**:上下文压缩后靠 git + ledger 恢复进度(最贵失败模式的解法)
- **每任务 fresh subagent + task review 双审(spec 合规+质量)+ 终审**
- **fix loop 5 轮上限**:R1-3 续用原 agent,R4-5 换更强模型;到顶裁决(park with ruling 或 BLOCKED),禁止静默丢弃 finding
- **Runtime Governance**:plan 与 spec 冲突 → 问人,不静默选边

## 好处(净效果)

1. 从"做完"变"做对"——Iron Law 封死"应该没问题"式提交
2. 从"写代码"变"先设计"——HARD-GATE 在 spec 阶段付掉返工成本
3. 从"大任务一把梭"变"bite-size 可审查"——上下文不爆炸,进度可恢复
4. 从"固定团队"变"按需专家"——省钱(turn 数 > token 价)且更快
5. 从"越用越熟"变"系统自进化"——失败/纠错反过来改进指令本身
