# SIM · Self-Improvement Memory

Google 与宾州州立大学团队的论文让 harness 优化器按反复出现的问题记录改动理由、预期结果、实测结果和评估上下文，供后续决定保留、调整、替换或移除旧改动。Harness 指给 Agent 配置上下文、工具、执行与验收的机制。[论文 §3.2](https://arxiv.org/html/2611.18856v1#S3.SS2) · [虎嗅解读](https://www.huxiu.com/article/4907380.html)

wade-ai 用一份按根因追加的 Markdown 记录实践这个方法，沿用现有的测试和项目约定。一次昂贵的漏验、重复犯错或换 Agent 后可重现的差异，值得留一条。

## 什么时候读、什么时候写

1. **复用前**，按症状或根因查项目现有记录和下方共享案例，例如「构建成功但没验证到目标产物」。看旧尝试依赖的版本、工具、环境和验收条件，再决定沿用、调整、替换或撤回。换项目、模型或运行环境时，用目标环境的相关用例复验。
2. **尝试前**，写下根因假设、准备改变的规则或检查，以及哪条用例应变好、哪条旧行为要维持。优先沿用同一基线和输入。能保留独立样例时，用它检查改动能否迁移。
3. **尝试后**，追加证据和判断。留住值得避免重试的失败。补记历史时标明「回顾性整理」，预期一栏写「当时无记录」。
4. **沉淀时**，优先更新已有的规则、测试或 skill，并链接记录。项目记录放到已有的工程笔记，缺省可用项目内的 `.ai/memory/sim.md`，保存方式遵守该项目约定。可迁移的经验经审阅后脱敏纳入 wade-ai，并在下方链接案例。

## 记录模板

按根因分组，每个根因下面追加尝试。已有条目可以直接追加小节。

```markdown
## <反复出现的问题 / 根因假设>

适用范围：<任务/入口/环境>
旧行为基线：<原始症状、对照版本或证据>

### <日期> · <规则、工具或测试的改动>

- 尝试与理由：
- 验证前预期：<预期修好什么，哪些行为继续成立>
- 评估上下文：<版本、环境、用例、命令，必要时写 Agent/模型>
- 实测：<实际结果、意外回归、未验证项、证据>
- 决定：<保留 / 调整 / 替换 / 撤回 / 待验证，以及适用条件>
- 关联：<规范、测试或后续复验入口>
```
