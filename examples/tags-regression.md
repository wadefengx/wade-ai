# Tags 回归案例

从一次文档站集成整理的脱敏案例。示例里的验收范围只针对这个功能。

给文档站增加可选的标签校验，开启时要求新增和已编辑文档填标签，历史文档照常构建。CLI 和构建插件消费同一份变更清单。清单明确为空代表该次没有要验证的文档；上下文缺失或计算出错时要报错。

## 验收场景

| 输入 | 在真实入口观察 |
| --- | --- |
| 新增或已编辑的文档缺标签 | lint 或构建按契约失败，报错指向实际源文件。 |
| 修正同一份输入 | 同一命令通过，站点生成预期内容。 |
| 旧文档一直没有标签 | 构建通过，能打开旧文档的生成页面。 |
| 显式传入空变更清单 | 校验零条变更，构建继续。 |
| 校验已开启，但缺少变更清单或计算失败 | 给出诊断和失败状态。 |
| 功能关闭 | 构建使用默认行为，标签功能的路由按约定不生成。 |

在实际构建工具里用隔离夹具复跑缺失、空清单、错误输入和修正后的输入，并读取旧文档生成的 HTML。消费者和 CI 的结果各自绑定目标提交和实际入口。上游版本未发布时，记录等发布后用可安装版本复跑消费者的构建和页面。

## 两次尝试

第一次为了零漏检，另写了一套按 CI 事件、子模块和容器挂载计算的变更范围，代码量膨胀，最后撤回。第二次改成所有检查共用一份清单，空、缺失、出错三种状态分开表达，保留下来。两次尝试的理由、实测和迁移判断见 [SIM-001](../memory/sim.md#sim-001)。这个案例的评审循环本身也留下了一条经验，见 [SIM-002](../memory/sim.md#sim-002)。
