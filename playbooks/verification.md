# 验证与回归

## 开改前

1. 把成功条件写成能观察到的结果。修 bug 时，优先复现 Wade 贴出的错误、用例或 CI 入口。能对比时，用相同的输入和配置保存一份基线结果。
2. 读项目脚本、CI 工作流和相邻的调用方，确定真实入口、预期产物和必须保留的行为。先挑最小的有效用例集，再按风险扩大。
3. 只改测试时，不动生产代码，逐项对照现有契约核对断言和快照的改动。覆盖率以项目规定的工具、统计范围和口径为准。和阈值比较时，先确认它是全量覆盖率还是新增代码覆盖率。
4. Wade 指定了端口、环境或账号时，就用他给的。不另起服务，也不换环境。

## 改完按影响验证

| 变更 | 优先验证 |
| --- | --- |
| Bug 或行为变更 | 原始复现修前失败、修后通过。检查同一根因影响的相邻入口。必要时在隔离环境里临时把缺陷改回去，确认回归用例真的能抓住它，验证完再恢复。 |
| 行为保持型变更：重构、升级、迁移、只改测试 | 用同一输入对比改前和改后：受影响页面的 UI、交互、样式，逻辑分支，单测，构建产物。只说「看起来一样」不算证据，要附截图对比、快照、产物 diff 或测试结果。 |
| API、路由、配置、数据迁移 | 当前输入、历史数据、开关状态、无输入和无效输入，都按契约表现。检查受影响的使用方，以及失败后的重试或回退。 |
| CLI、CI、构建 | 用真实命令跑正例和反例，确认调用到了预期的任务。检查退出码、诊断信息和构建产物。命令退出码为 0 时，确认它实际执行和检查了什么。〔[SIM-001](../memory/sim.md#sim-001)〕 |
| 公共包、SDK | 先用本地链接或打包产物，在真实的使用方上验证。有发布流程时，等可安装的版本发布后，在同一个使用方上安装并复测，再推广。 |
| UI | 对照实际预览和当前设计源。验证关键交互、各种内容状态和受影响的旧流程。按场景检查窄屏、主题、键盘和无障碍。 |
| 修测试、覆盖率或 CI | 对照原始日志和统计口径复跑。确认测试没有被跳过。验收后检查 diff 里的快照、生成物和配置变动。 |
| 跨平台：Windows、Linux、容器、CI | 只报告真正在那个平台上跑过的结果。没有目标平台时，写清楚已在哪些平台验证，再给出在目标平台上 100% 复现原问题和验证修复的步骤。 |

核心用例跑完后，按影响执行项目的 lint、类型检查、构建、相邻测试套件和 CI 门禁。需要比较的结果，要绑定同一个提交、输入和环境。遇到超时、服务缺失或已有的失败，先定位原因，把独立的验证做完，留下可以复跑的命令和条件。

## 什么能证明什么

| 说法 | 需要的证据（当前版本） | 不够的证据 |
| --- | --- | --- |
| 测试通过 | 预期的用例确实执行了，附范围和结果 | 以前的结果；执行了 0 个用例 |
| 构建成功 | 预期的构建任务执行完、退出码为 0、检查了所需产物 | lint 通过；什么都没做的命令 |
| Bug 已修 | 原始症状的复现现在通过 | 改了代码，推测已经修好 |
| 子代理或工具完成了 | diff 里有对应的改动，并且自己复跑过 | 对方报告「成功」 |
| 需求满足 | 逐条核对验收标准 | 只看测试通过 |
| CI 通过 | 在 CI 页面或 API 上看到这个提交的状态 | 本地通过；CLI 没有权限、读不到状态 |

## 常见误判

- **跑了等于验了。** 命令退出 0，但过滤条件写错、用例被跳过，或者变更清单为空，实际什么都没检查。看执行数量和产物。〔[SIM-001](../memory/sim.md#sim-001)〕
- **模拟环境的假象。** 浏览器设备模拟会改设备像素比，界面看起来被放大；Apple Silicon 上用模拟方式跑 amd64 镜像会变慢，可能偶发超时；CI 和本地生成的类名哈希可能不同，导致快照不一致。先确认现象在真实环境里是否存在，再判断是不是产品问题。快照里依赖环境的部分，在测试里统一处理掉。
- **CI 的 checkout 不完整。** 浅克隆或缺少比较基准时，变更范围可能为空、出错，或者把提交时间当成内容的修改时间。在 CI 和本地各跑一遍再下结论。
- **旧进程和缓存。** dev server、热更新、构建缓存或已安装的旧版本包，都可能还在用旧代码。复测前确认运行的是当前改动。
- **权限不够被当成通过。** CLI 对某些平台返回 401 或 404 时，CI 状态是「受阻」，要去网页上确认，或者交给 Wade 确认。

## 怎么报结果

- 写明版本或工作区改动、命令或用例、环境和实际结果。关键处附上 CI 链接、截图、产物路径或日志片段。
- 一项检查一个状态：**通过**、**失败**、**跳过**、**未运行**或**受阻**。只跑了部分套件时写明范围。平台、容器和模拟环境如实标注。
- 依赖没就绪时，写下「等什么 → 在哪里 → 用什么输入 → 看什么结果」。完成的部分照常交付，依赖恢复后再验收剩下的项。
- 例如：「本地单测和生产构建通过，容器里使用方的 smoke 测试通过。独立的扫描任务跳过了。线上验证要等新版本发布后，分别用历史链接和新链接走一遍入口。」

例子见 [Tags 回归案例](../examples/tags-regression.md)。
